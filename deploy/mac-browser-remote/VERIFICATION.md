## 已修复：Mac 认证方式协商

用户已完成正式网站登录与 TOTP，但打开 My Mac 连接失败。Mac 的 RFB 握手提供安全类型 `30, 33, 36, 2, 35`，其中包含独立密码使用的 VNC 类型 2。网页实际弹出用户名请求；Guacamole 1.6.0 的 VNC 插件会在底层请求用户凭据时发送这个提示，且没有暴露指定安全类型的连接参数。

用户选择保留独立 VNC 密码。`guacd/vnc-password-auth.patch` 在未配置 username 时调用 `SetClientAuthSchemes`，限定为 VNC 类型 2；有 username 时保留原有协商。实际重连后不再要求 Apple 认证的用户名，能够传输 Mac 画面，用户手动登录后确认当前桌面显示正常。临时 debug 日志已关闭，没有修改用户凭据、TOTP 或 Mac 系统偏好。

认证补丁不能承诺跳过 macOS 自身的登录界面。实机出现过“本机未锁屏，但 VNC 显示登录窗口”的情况，用户在该画面正常登录后进入当前桌面。重建 guacd 容器会断开现有 VNC 连接，重连可能需要再次在远程画面登录；不要把这个画面直接判断为物理 Mac 已锁屏。macOS 登录密码没有写入本工程的配置或数据库。
